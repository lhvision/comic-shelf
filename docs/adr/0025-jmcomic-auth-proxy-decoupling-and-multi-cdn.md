# ADR 0025 — 禁漫 (JMComic) 受限画卷鉴权解析、控制流/数据流代理分流与多 CDN 容灾决策

- **日期**：2026-09-18
- **状态**：Accepted
- **关联**：承接 ADR 0013 (哔咔数据源接入规范与架构定力)，扩展 `CONTEXT.md` 禁漫漫画、受限画卷鉴权解析、控制流与数据流代理分流、多 CDN 动态轮换降级

## 背景

在纸间（Paper Room）的日常运行与馆长收录场景中，禁漫天堂（JMComic）作为核心历史图源之一，面临两大现实网络与平台限制挑战：

1. **受限画卷权限墙（Login-Restricted Albums）**：禁漫平台对部分标记为限制级、特定敏感题材或特定作者的作品实行权限隔离，未登录访客（Guest）在访问该本子页面或接口时会被重定向至 `/login` 或直接报 404/下架假象。此前纸间后端缺少账号体系集成，导致此类合法车号在收录时被误报为“不存在或已被下架”；
2. **出站网络割裂与域名迟滞（Domain-Specific Latency & GFW Blocking）**：
   - 禁漫的出站请求呈现鲜明的双层结构：一方面，域名重定向探测（`jm365.work`）、API 域名配置更新与 HTML 页面拉取极易遭受大陆网络拦截（超时甚至重置连接）；另一方面，画页大图分流 CDN（如 `cdn-msp*.jmapiproxy*.cc`）流量巨大，部分用户直连边缘 CDN 反而比代理更快，或受限于代理流量不愿大图走代理；
   - 此前代码中，网页域名解析与画页下载全量使用裸 `curl_cffi.Session` 且无代理配置，而 upstream `jmcomic` 默认字典却硬编码了 `127.0.0.1:7890`，导致行为存在严重隐式漂移；
3. **上游 WAF 拦截与假 200 报文破坏（Upstream WAF Disguise Trap）**：部分 CDN 节点在遭遇流量突发或拦截时返回 HTTP 200 带有 HTML 验证码或错误提示，单域名固定重试极易将错误文本载荷当作图片写入磁盘，破坏本地离线库并导致后续以图搜图 Sidecar 崩溃（见 `docs/PITFALLS.md` 第 60 条）。

## 决策

### 1. 坚守车号收录交互定力（拒绝泛化模糊检索冗余）

- **否决在 UI 引入在线模糊搜索**：经过论证，纸间坚守“本地优先个人收藏夹，禁止作为泛化爬虫或公开图床”（`AGENTS.md` Rule 0）的核心定位。收录面板（`ImportPanel.vue`）维持输入精准车号（`JM523607` 或纯数字）的既有形态；
- **精准定位破壁核心**：用户痛点的本质是“受限车号需登录才能查看”，打通底层受限鉴权即可彻底解决收录受阻，无需在前端堆砌冗余的在线检索与复杂的搜索卡片流。

### 2. 账号凭据管理与会话自愈保活 (`backend/data/jm_session.json`)

- **环境变量集中配置**：在 `.env` 中提供 `JM_USERNAME` 与 `JM_PASSWORD`，与哔咔 `PICA_EMAIL` / `PICA_PASSWORD` 保持完全一致的工程规范；
- **凭据换取与长效缓存**：首次请求或冷启动时通过客户端接口自动完成登录并置换出包含 `AVS` 及会话标记的完整 Cookies，持久化存储于 `backend/data/jm_session.json`（TTL 7 天）；
- **透明自愈重登（Self-Healing Auth）**：当请求遇到登录重定向、页面提示“需要登入”或 `album_missing` 时，后端底层自动清空失效凭据缓存并触发静默重新登录重试一次；若依然受限或未配置账号，向前端返回明确的靶向友好指导（`“该禁漫作品受权限保护（需登录查看），请在 .env 中配置 JM_USERNAME 与 JM_PASSWORD 后重试”`），消除 404 误导；
- **匿名模式平滑兼容**：未配置账号时完全不影响公开普通车号的匿名解析与排行榜拉取，保障零配置开箱即用。

### 3. 控制流与数据流解耦代理分流架构 (Control & Data Plane Decoupling)

- **控制流代理（`JM_PROXY`）**：针对域名嗅探、动态域名更新、HTML 页面与登录认证等高阻断率请求，统一接入 `JM_PROXY`（支持 HTTP / SOCKS5）；
- **数据流分流模式（`JM_IMAGE_PROXY_MODE`）**：
  - `auto`（默认）：若配置了 `JM_PROXY`，画页下载跟随走代理；未配置则直连；
  - `direct`：画页下载强制直连，彻底保护代理流量配额并利用直连 CDN 峰值带宽；
- **拒绝过度工程**：主动剔除冗余的独立图片代理配置（`JM_IMAGE_PROXY`），保持单一主代理加双态分流的最简模型；
- **消除隐式硬编码**：彻底覆盖 upstream `jmcomic` 默认配置中硬编码的 `127.0.0.1:7890`，未配置代理时干净透传直连，杜绝因本地未开启 7890 端口引发的隐式网络故障。

### 4. 多图源统一会话持久化与深度防御 (Unified Provider Secure Session & Defense-in-Depth)

- **基类会话管理收敛（`ComicProvider.save_secure_session`）**：针对第三方图源（PicAcg、JMComic 以及未来任何需鉴权站点）的持久化，将安全落盘能力统一下沉至 `ComicProvider` 基类：
  - **零 TOCTOU 权限真空**：采用 `os.open(temp_file, os.O_WRONLY | os.O_CREAT | os.O_TRUNC, 0o600)` 保证文件创建第 0 微秒即具备 POSIX 私有权限，杜绝共享 NAS 或多用户宿主机下的窥探窗口；
  - **原子替换（Atomic Replacement）**：临时文件写入完成后使用 `os.replace` 原子覆盖，防止并发覆写或系统异常退出产生坏损的半截 JSON；
  - **优雅注销与加载防御**：统一封装 `load_secure_session` 与 `clear_secure_session`，消灭分散胶水代码并完成未用包（如 `import json` / `import os`）的安全剔除；会话加载提供类型安全时间戳解析容错；
- **并发防惊群自愈重登（Thundering Herd Guard）**：在遇到受限画卷触发 `force_refresh=True` 时，双检锁内集成 15 秒凭据冷却窗口，复用并发首个线程成功换取的会话，杜绝高并发多任务瞬时打爆官方登录接口；
- **官方集群候选池动态轮换与强制 HTTPS**：整合禁漫官方 6 组 CDN 节点（`JmModuleConfig.DOMAIN_IMAGE_LIST`）。在单页下载重试循环中，当遇到超时、连接中断、HTTP 403/502 时，自动平滑替换 URL 域名至下一个候选 CDN 节点，并显式锁定 `scheme="https"` 防止中间人嗅探与明文降级；
- **SSRF 域名安全沙箱校验**：在域名嗅探与 CDN 候选池中全量启用 `_is_safe_remote_domain`：
  - 前置校验 `any(c in d for c in "/?#@%")`，在端口切分前阻断类似 `trusted.com:80@127.0.0.1` 的后置凭据伪造注入；
  - 剥离 IPv6 方括号及端口号，阻断如 `127.0.0.1:8080`、`[::1]:8080` 绕过；
  - 阻断私有 IP、回环网段（`127.0.0.1`、`192.168.x.x`、`10.x.x.x`、`169.254.169.254`）及内网私有后缀（`.local`、`.internal` 等）；
  - 阻断八进制 IP（`0177.0.0.1`）与 URL 凭据字符（`attacker.com@127.0.0.1`）；
  - 移除候选池兜底放行逻辑，无安全候选时直接抛出异常拒绝出站；
- **日志与敏感凭据全链路脱敏**：新增 `_mask_sensitive` 正则过滤器，在记录日志前无差别将 `JM_PASSWORD` 与代理认证凭据清洗替换为 `***`，对短密码提供协议上下文保护，彻底避免第三方网络库异常文本泄漏明文密码；
- **严格二进制魔数防伪验证**：单页载荷必须通过 JPEG (`\xff\xd8\xff`)、PNG、WebP (`RIFF....WEBP`)、GIF 或 AVIF 首字节魔数检测；若检测到上游 WAF / CDN 伪装的 HTML 拦截页，坚决不落盘并立即标记当前节点故障、轮换至下一个 CDN 节点重试，彻底落实错题本防范红线；解密分割数计算增加异常兜底，保障极端切片参数平滑回退。

## 影响与收益

1. **破除受限本子收录壁垒**：禁漫敏感题材、特定作者及限制级作品 100% 支持通过车号无感解析收录；
2. **多图源凭据安全标准收敛**：通过基类统合 PicAcg 与 JMComic 的持久化生命周期，为未来任意新增平台建立统一的零漏洞凭据安全规范；
3. **网络通达性与吞吐跃升**：控制流阻断率降低为 0，数据流支持直连/代理灵活分流，多 CDN 轮换消除单点丢包阻塞；
4. **架构纯粹与稳定性**：零冗余搜索代码膨胀，完全复用现有收录面板与单卷/多章节模型，所有凭据与网络故障均具备明确的中文诊断与自愈能力；彻底清理死代码与重复抓取编排。
