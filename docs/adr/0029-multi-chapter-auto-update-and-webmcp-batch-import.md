# ADR 0029 — 多章节自动追更巡检、断更熔断保护与 WebMCP 批量收录

- **日期**：2026-09-25
- **状态**：Accepted

## 背景与问题

纸间此前多章节漫画（合集、连载）的更新依赖馆长在详情页手动点击「刷新资料」；当藏书中包含大量仍在连载的作品时，逐一人工检查极其繁琐。同时，在批量收录场景下，Web 界面与 WebMCP 原先仅暴露单本导入接口，通过智能体或外部脚本导入大批量作品时易引发瞬时请求拥堵。

本决策解决两个问题：

1. 如何为多章节作品提供安全、轻量、自律的自动追更巡检，并防止对长期停更/完结作品产生无意义的远端探测；
2. 如何在维持前端 Web 界面极简纯粹的前提下，为 WebMCP 提供鲁棒且防风控的批量收录能力。

## 核心决策

### 一、多章节自动追更：仅限非本地多章节，单 Worker 串行守护调度

1. **适用边界**：
   - 必须满足 `is_multi_chapter == true`（话数 > 1）且 `source != 'local'`（非本地自建源）；
   - 若本子已由馆长重新装订（`custom_pages == true`），严格遵守 ADR 0020 的重新装订保护原则，**绝对不触碰自动追更**。
2. **轻量守护协程**：
   - 在 FastAPI `lifespan` 中挂载单一后台异步协程，按 1 小时为周期进行到期唤醒扫描；
   - 针对到期项（`now - last_auto_checked_at >= auto_update_interval_days * 86400`，默认 15 天），采用单并发串行队列逐本处理，每次探测之间**强制休眠 3~5 秒**，单次唤醒最多处理 10 本，避免长时间占用单 Worker 并杜绝触发上游图源风控；
   - 探测复用 `JMProvider` 现有的增量模式（`existing=existing`），仅拉取单页 HTML 校验话数，**0 额外画页网络请求**。

### 二、断更判定（Hiatus Detection）：30 天阈值熔断保护与手动自愈

1. **熔断判定**：
   - 远端最新更新时间（优先 `updated_at`，缺省取 `published_at`）距今超过 **30 天（1 个月）** 的多章节作品，系统自动将其判定为「断更/完结」；
   - 处于断更保护状态的作品自动跳过后台定时巡检，不再向远端发送任何请求，杜绝无意义的网络消耗。
2. **自愈恢复**：
   - 详情页对断更作品展示轻量状态提示（「已超1个月未更新，已暂停自动巡检」），并保留手动「刷新资料」按钮；
   - 一旦馆长手动点击刷新且远端返回了 30 天内的新更新时间，系统自动重置断更标记，将其重新纳回自动追更调度环。

### 三、新章节追更成功后的状态自愈与联动

1. **阅读状态自愈**：
   - 严格维护 `CONTEXT.md` 不变量：若该本子原为「已读（Completed）」，追更新章节后**自愈回退至在读（Reading）状态**，并在书架案头显式浮现；
2. **画页缓存策略**：
   - 若本子在更新前已处于「全本缓存完毕」状态（`cached_pages == page_count`），系统自动投递新章节画页离线预缓存任务；
   - 若原先为部分缓存或按需浏览，则**仅追加元数据与全局页码**，画页保持懒加载，绝不擅自滥用馆长硬盘与带宽。
3. **前端感知**：
   - 通过 SSE `library_changed`（action: `auto_update_append`）广播事件，协同客户端无需整页刷新即可实时感知话数更新。

### 四、WebMCP 批量收录：保持 UI 现状，通道独立暴露与单本隔离容错

1. **UI 纯粹性**：
   - 书架 Web 界面维持现状，不堆砌复杂的批量多选复选框，保护阅览室的清爽阅读体验；
2. **工具契约**：
   - 在 `useShelfWebMCP` 中新增专门的 `shelf_batch_import_comics` 工具（仅限馆长权限）；
   - 支持传入字符串数组或多行纯文本（自动正则抽取有效车号与图源）；
   - 内部队列串行调度，每本间隔 1.5 秒，若单本遇到 404 或网络波动，**单本捕获错误记录到 `failed`，绝不阻断后续本子的入库**；已存在条目秒级命中缓存跳过；
   - 最终返回结构化明细报告 `{ total, succeeded, skipped, failed, results }`，供调用 Agent 准确向馆长汇报。
