# ADR 0019 — 批次增量预缓存、空洞自愈切片与宏观全局进度契约

- **日期**：2026-09-14
- **状态**：Accepted

## 背景

为了保护远端图源 CDN 避免触发高频封禁，并防止服务器磁盘与网络 I/O 过载，系统通过环境变量 `COMIC_SHELF_MAX_PREFETCH`（默认 600 页）为全量预缓存设立了单次预算门禁。

然而原有的预缓存实现存在以下结构性缺陷：

1. **死板首屏切片与无法推进**：后端调度逻辑硬编码为 `range(1, min(page_count, MAX_PREFETCH) + 1)`。对于一本 1500 页的长篇漫画，第 1 次点击缓存了 1~~600 页；第 2 次点击时，系统依然只检查 1~~600 页，发现本地磁盘全部命中便瞬间结束，**永远无法推进至第 601 页及之后**。
2. **跳读空洞与配额浪费**：读者若曾使用阅读器跳读中后段章节（例如翻阅了 650~660 页），传统连续区间切片容易重复探测或打乱顺序。
3. **微观进度导致假终态认知**：如果单批任务将 `total` 设为 600，批次完成时显示 100%，会给读者造成全书已下载完毕的假象，与实际全书未就绪状态产生严重割裂。

## 决策

1. **未缓存画页空洞自愈切片（Gap-aware Sequential Slice）**：
   - 全量预缓存触发时，后端先执行轻量级磁盘自愈校验（`reconcile_cached_pages`），精准提取全书所有 `p.cached == False` 的画页序号列表；
   - 严格按全局页码升序截取前 `MAX_PREFETCH` 页：`[p.index for p in meta.pages if not p.cached][:MAX_PREFETCH]`；
   - **自然自愈与前置重试**：读者跳读已落盘的页面会被透明跳过，上一批偶发失败的断页自然排在最前列优先重试，随后无缝顺延后续新页面，精确用满单批下载预算。

2. **宏观全局进度契约（Macro Global Progress Accounting）**：
   - 后台任务（Job）进度与事件广播统一以全书总页数作为唯一真理源：`job.total = meta.page_count`，`job.prefetched` 表示全书累计已缓存页数；
   - 严格契合 `CONTEXT.md` 的「未达终态不进位法则（99% 封顶律）」；未完全就绪时广播 `cache_partial`，全书就绪时才广播 `cache_complete`。

3. **幂等性与终态短路（Idempotency & Completed Short-circuit）**：
   - 在 `POST /api/library/{source}/{source_id}/cache` 入口处检测：若全书已 100% 本地化（`cached >= page_count`），直接返回 `complete=True`，彻底杜绝无意义后台守护线程启动。

4. **透明微交互与双态 Toast 契约（Two-tier Completion Feedback）**：
   - 前端（`useChapterCache.ts`）在任务结束时区分状态：
     - 若全本就绪：提示 `已全部缓存到本地（共 N 页）`；
     - 若批次结束但全书尚未就绪：提示 `已完成当前批次（已本地化 X/Y 页），可再次点击“缓存全部”继续下一批`；
   - 操作栏按钮实时更新为 `缓存全部（已缓存 X/Y）` 并恢复可点击状态，打通连续点击顺延的心流闭环。

## 后果

- **正面收益**：
  - 超长篇漫画支持平滑断点续存与步进下载，完美解决 600 页卡死无法推进的问题；
  - 维持 `MAX_PREFETCH` 对 CDN 防封禁和服务器稳定性的安全底线；
  - 进度显示、按钮状态与 Toast 引导全程自洽透明，零认知断层。
- **注意事项**：
  - 若用户希望一次性直接拉完全本，依然可通过增大宿主机环境变量 `COMIC_SHELF_MAX_PREFETCH` 覆盖默认步长。
