# ADR 0041 — 画页文字提取与台词索引同步的职责边界

- **日期**：2026-11-22
- **状态**：Accepted
- **关联**：[领域术语](../../GLOSSARY.md)、[ADR 0017](./0017-comic-dialogue-fts-and-bubble-overlay.md)、[ADR 0028](./0028-dialogue-semantic-search-separate-exit.md)

## 背景

需求是让高性能机器直接处理本地或局域网映射路径中的画页，并可在同机完成入库。
现有 OCR 按页增量，台词同步按本增量；台词索引已独立存于 `comic_dialogues.db`，正常本机事务更新不需要停服务或重启。
HTTP 同步接口没有被使用，却引入机器令牌、网络通知及重试分支。GPU-only 环境也没有后端依赖，不适合直接导入后端入库。

原 HTTP 接口只将已有伴生文件同步到台词索引，不执行图片识别。当前落地的是文件提取与本机增量同步，尚未提供平台按需识别、翻译或译文保存流程；后续在线翻译需要单独确定触发入口、识别执行位置和结果归属。

## 决策

1. 移除 OCR 同步 HTTP 路由、专用响应模型、权限放行、通知及其 URL / 令牌参数。其他机器令牌接口保留。
2. OCR worker 只读取画页、写 `.ocr.json` 并报告提取状态，不读机器令牌、不访问 SQLite。保留既有识别引擎、气泡聚类和伴生格式。
3. 保留书库图源 / 书号 / 页码选择与单页输入；新增 `--directory` 递归处理普通图片目录，不自动收录或推断作品身份，不混用书库过滤条件或册数上限。
4. 路径解析、规范目录名和文件清单共用 `app.ocr.files`，格式复用已有 Pillow 的光栅读取注册表；跳过隐藏项与内部符号链接，拒绝同目录同主体文件名的输出冲突。无效显式路径或过滤条件直接报错，不改扫其他书库。
5. 新鲜合法的伴生文件默认跳过，仅 `--force` 重提；共享标准库 `app.file_io` 独占创建临时文件、遵循宿主 umask、刷盘后原子替换，并在异常时清理。识别时以普通文件描述符读取图片和处理 EXIF / 首帧；源图变化时拒绝发布，新结果记录源图大小与修改时间，失败保留旧有效结果。
6. `ocr.sh run --sync-local` 先校验输入、用应用环境初始化独立台词表，再用 OCR 环境提取，最后由应用环境增量入库。提取增量命中也同步；部分失败仍同步已有结果，任一步失败保留非零退出码，重跑无需强制重提。
7. 本机同步入口为 `python -m app.ocr.sync`，仓库脚本 `scripts/sync_ocr.py` 仅调用它。默认镜像已有后端包，可直接执行该入口，不添加 OCR 推理依赖或模型。点名同步不顺带清理其他书籍的索引；全库同步保留孤儿清理。
8. 索引增量以伴生文件清单、文件状态及 `album.json` 的签名判断；删除旧的最大 mtime 比较及非标准目录探测。旧元数据自动加列，对应漫画下次同步时更新一次。读取逐层拒绝目录 / 文件链接，变化中的输入不提交部分索引。
9. 调试 dump 默认使用随机私有临时目录，输出保留图源 / 书号 / 章节路径；缓存须匹配原图且结构合法，原子发布不覆盖其他结果。拒绝其他用户可控制的输出目录，重聚类支持递归读取。

## 约束与代价

### 2026-11-22 补充：保守分类、失败恢复与资源边界

- OCR 文件边界、分类和同步入口集中到 `app/ocr/`；CLI 为 `python -m app.ocr.sync`。
- 广告由平台标识、下载引导、链接或二维码的组合证据及可用气泡面积识别；明确招聘结合联系方式也可识别海报。
  只按位置、长句、重复次数或普通词过滤正文的规则删除。广告保存为副文本，原始伴生文件保留；
  `jm/625761` 第 32 页作为回归样本，与开篇对白、英文短句及角落水印混排共同验证。
- 分类版本参与同步签名；提取版本、引擎与置信度参与伴生新鲜度。旧资产下一次提取会更新一次，分类调整仅需同步。
- 逐页关键词、每批 64 条向量写入磁盘临时表，完成后发布；坏资产不替换旧关键词，关键词发布同时清除旧向量。
  向量分别记录源与模型签名，编码失败的普通重跑只补向量；CLI 报告实际失败，业务页码修改仍可保留关键词降级。
- 小库缓存预算 32 MiB，大库每块扫描 1024 条精确检索；查询与回表共享读快照。
  `sync --limit` 限制本轮待更新册数，`--skip-vectors` 允许先建关键词，`run --sync-limit` 独立于提取 `--limit`。
  分块增加大库读取开销；它降低内存峰值，不保证低功耗 NAS 吞吐或 CPU/I/O 隔离。
- 伴生 JSON 先按 2 MiB 有界读取，每页最多 1024 气泡、单条最多 8192 字符；图片提取前限制 50 MiB 与 4000 万像素。
  超限失败保留旧结果，线程推理尚无可强制终止的单页硬超时。
- 同步包含原图状态，新资产核对 `source_image`；历史缺失记录为未核验而非清库。
  关键词提交与存储修改共用本机书籍文件锁，提交内检查预期全局索引版本与文件签名，冲突重试。
- 语义搜索最多一个并发、关键词最多四个；按 IP 分别限频并快速返回 429，闲置记录有期限与总数预算。
  不增加 Redis：项目为单 API worker，文件锁与 SQLite 负责同机提交，本机令牌桶负责 HTTP 预算。
- `sync --status` 与馆长状态接口报告待建、失败、模型不匹配和历史未核验页数；统计不进入访客搜索响应。
  删除不再使用的分类位置/重复参数，以及重复的气泡结构和坐标校验实现。

- 同步复用现有按本增量实现，不复制或替换整个数据库；不增加索引发布协议或另一套搜索实现。
- 高性能机的本地 `data` 可一条命令完成提取和同步。映射盘用于读画页、写伴生资产；SQLite WAL 数据库须由所属主机在本地访问，不能因目录结构一致就跨机器打开 NAS 的数据库。
- 语义召回使用服务一致的模型与依赖环境；编码器不可用时关键词仍可入库，既有逻辑会清除该本旧向量。没有目标 NAS 的性能实测，不能把全库 CPU 编码参考当作每次增量同步的耗时。
- 默认生产依赖导出须与 OCR 迁移前逐字节一致。镜像仅增加轻量 CLI 源码，算力环境的依赖和模型仍独立安装。

### 2026-11-23 补充：旧向量核验与模型状态

存量向量缺少源签名、模型签名或同步元数据时返回 `model_mismatch`，关键词继续可检索，原资产与旧向量保留，
本机普通同步补建后恢复。只检查实际有向量的漫画，避免没有向量的待建漫画阻断已核验语料。
模型会话、维度和签名以完整状态发布，单次编码固定状态，查询与每批建库核对预期模型；初始化时观察到文件变化不发布。
状态统计与查询复用同一 SQLite 读快照；缺失漫画的普通读取不创建锁，文件锁由程序管理，服务和同步使用同一 UID。
上述防护使用标准库，默认生产依赖清单不变；测试与文档由 `.dockerignore` 排除，模型和索引属于数据卷，
因此只有后端源码层发生变化，精确镜像字节数以实际构建测量为准。

后续完整画页翻译应从伴生资产取原文，不能把经过筛选的搜索语料当作全部画页文字。当前伴生结果已有气泡文字、外接框和阅读顺序，但未保留逐行识别框；`lang` 固定为 `zh`，不能据此自动判断源语言，气泡编号也会在重提后重新排序，旧译文不能只凭相同编号继续绑定。

## 验证

针对普通目录、过滤条件、输出冲突、符号链接、原子写入、权限、失败保留、并发临时文件和本机同步重试执行回归；同时验证台词检索、语义召回、鉴权与原 HTTP 入口的移除。
执行 `vpr check:py`、相关 `vpr test:py`、`vp check --deny-warnings` 及生产依赖导出对比。
