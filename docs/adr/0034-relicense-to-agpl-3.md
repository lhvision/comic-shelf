# ADR 0034 — 全仓开源协议升级为 GNU AGPL-3.0 架构决断

- **日期**：2026-10-17
- **状态**：Accepted

## 背景与问题

纸间（Paper Room）定位于「本地优先的个人漫画收藏馆」，其核心不变量与宗旨为打造属于馆长本人的高保真私有数字藏书馆，坚决禁止作为泛化爬虫工具或商业化公有云图床。

在既往演进中，项目根目录采用了宽松的 MIT License。然而随着系统能力不断深化（特别是引入原生 PDF 漫画收录与版面分析能力），底层协议面临法律合规与开源生态层面的双重挑战：

1. **依赖库协议传染与合规性隐患**：
   - 纸间在后端引入了 `pymupdf>=1.24.0`（参见 [ADR 0024](./0024-pdf-comic-ingest-and-dual-track-chapter-splitting.md)），用于高性能 PDF 页面提取、解密与版面流分析。
   - PyMuPDF 采用 Artifex 双重授权许可：商业授权或 **GNU AGPL-3.0**。在未购买 Artifex 商业授权的前提下，纸间作为分发 PyMuPDF 绑定调用的开源工程，若在根目录声称 MIT License，存在潜在的许可证冲突与合规缺陷。
2. **防范闭源云化（Anti-SaaS 保护）**：
   - 传统 GPL-3.0 仅在「二进制或源码分发（Convey）」时触发开源义务，存在著名的「ASP/网络服务漏洞（Application Service Provider Loophole）」。第三方服务商若将纸间包装为在线收费 SaaS 平台或闭源在线图床，在 GPL 或 MIT 下无需回馈任何改动。
   - 这严重违背了纸间「本地优先、馆长私有」的初衷。

为此，亟需重新审定项目开源协议，并对全栈所有依赖进行严格的协议兼容性审计。

## 核心决策

### 一、全面采纳 GNU AGPL-3.0 协议

项目全仓整体开源许可升级为 **GNU Affero General Public License v3.0 (AGPL-3.0-or-later)**：

1. **合规性自愈**：
   - 完全遵循并继承 `pymupdf` 的开源授权条款，消除了法律上的潜在侵权风险，使整个项目的开源法律链条无懈可击。
2. **强约束网络服务传染性（Section 13）**：
   - 依据 AGPL-3.0 第 13 条款（Remote Network Interaction），任何机构或个人若将纸间修改并在网络端提供在线交互服务（SaaS/PaaS），必须无偿向所有网络使用者公开其完整对应源代码（Corresponding Source）。
   - 从法律武器层面筑起护城河，强力遏制将纸间改造成闭源公有云、付费套壳站点或网络爬虫贩售平台的行为。

### 二、依赖库兼容性审计与验证

对项目后端与前端所有引入的三方依赖进行单向兼容性交叉审计：

1. **宽松开源协议（Permissive Licenses）单向兼容**：
   - 后端依赖：`FastAPI`、`uvicorn`、`pydantic`、`pillow`、`httpx`、`curl_cffi`、`jmcomic` 等均为 MIT / Apache-2.0 / BSD 协议。
   - 前端依赖：`Vue 3`、`VueUse`、`Pinia`、`Vite+`、`UnoCSS` 等均为 MIT / Apache-2.0 协议。
   - **法理结论**：宽松协议允许代码被包含、衍生并在更严格的 Copyleft 协议（如 AGPL-3.0）下发布，不会产生任何冲突。
2. **同类与互操作 Copyleft 依赖**：
   - `pymupdf`（AGPL-3.0）：完全同构继承，天然契合。
   - `imsearch`（GPL-3.0）：用于局部特征点以图搜图。纸间通过独立容器进程与 HTTP REST API 网络隔离调用；退一步讲，AGPL-3.0 第 13 条亦明确保障了与 GPLv3 代码在单个程序中联合分发的互操作权利。

### 三、单仓同构统一授权

1. 保持仓库统一性，不拆分多重协议（如前端 MIT + 后端 AGPL），避免给使用者带来「许可拼图（License Mosaic）」的认知负担。
2. 无论是后端服务、前端 SPA、还是 `extension/` 浏览器扩展，统一在 AGPL-3.0-or-later 下分发。
3. 同步变更项目元信息：
   - 替换根目录 `LICENSE` 为 GNU AGPL-3.0 官方完整文本；
   - 在 `package.json` 显式标明 `"license": "AGPL-3.0-or-later"`；
   - 在 `README.md` 顶层致谢中明确标注 PyMuPDF 的 AGPL-3.0 授权与贡献。

## 效果与收益

1. **法律合规闭环**：彻底解决 `pymupdf` 的协议继承要求，项目在开源合规治理上达到生产与商业审计级水准。
2. **不伤害终端私有化部署**：
   - 对于馆长个人使用、内网穿透自用、私有家庭 NAS 部署、Docker 容器化运行，AGPL-3.0 不构成任何额外负担；
   - 馆长享有最完整的自由度（运行、修改、私有研究、离线阅览）。
3. **生态防护与代码回馈**：
   - 杜绝商业公司「吸血式」套壳云化；任何基于纸间二次开发的在线分叉版本，其成果都必须以 AGPL-3.0 反哺开源社区。
