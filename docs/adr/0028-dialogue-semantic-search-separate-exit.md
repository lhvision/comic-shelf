# ADR 0028 — 台词语义召回：独立出口，不与关键词混排

- **日期**：2026-09-23
- **状态**：Accepted

台词检索此前只有一条腿：FTS5 trigram 字面匹配（简繁归一后已做到字形无关，见 ADR 0017 修订）。字面不通的查询完全落空——搜「告白」拿不到「我喜欢你」，搜「脸红」拿不到「满脸通红」。本轮补上第二条腿：量化 `bge-small-zh-v1.5`（ONNX，23MB）把台词与问题都编成 512 维归一向量，余弦取近邻。

三条决定各自否决了什么：

**一、语义只做成独立出口（`GET /api/search/dialogue-semantic` 与 MCP `search_by_meaning`），不并进 `search_dialogues` 做混合排序。** 现有关键词出口的排序里掺了本人视角（收藏、完读率、站内热度，ADR 0017 决策 9），`rank_score` 又是"本次候选池内 min-max 归一"——换一次查询就换一把尺子。把余弦相似度塞进同一根标尺，前端与 agent 都无法区分"这句意思像"和"这本你读过"，而混合排序要重测的口径（错题本 #139 的"计数字段与身份无关"）比语义召回本身的价值大得多。因此新出口用**独立字段 `similarity`**（余弦，不做池内归一、不掺业务信号；但**只在同一次查询的结果之间比高低**——实测真命中与噪声的分数区间重叠，跨查询比较与绝对阈值都不成立，"没找到"��由 `reason` 表达）、**气泡粒度**返回、**不掺业务信号**，两个出口各自成立。要字面命中就用老出口，要换种说法也说得出就用这个。

**二、向量存在台词专库里（`comic_dialogue_vectors`），不外挂、不进识图侧。** 识图侧已是独立 Rust sidecar 自带向量索引（ADR 0026 的分域口径），文本向量与图像向量除了都叫"向量"以外没有任何共同点，混库只会让两边的重建与迁移互相牵连。同库异表则白拿现有的一切：`*/ocr/sync` 入库、删书与孤儿清理、`comic_dialogues.db` 整库备份即带走语义腿。

**三、语料向量在本机算，不挪到算力机。** 算存分离的前提是"画页推理很贵"（1764 页 ≈ 8 分钟 GPU），而文本编码实测 **184 行/秒（CPU）**，整库 7544 行 41 秒、单本约 1 秒。为这点开销新增一种伴生文件格式、再让 NAS 跨 SMB 读它，是用协议复杂度换不存在的瓶颈。所以向量的产出挂在 `sync_comic_dialogues` 尾部（每同步一本顺手重编那一本，新书不会静默落后），只有全量重建是显式动作（`POST /api/search/dialogue-vectors/rebuild`，馆长/Machine Token）。查询编码必须在服务进程里做——问题什么时候来是不可预知的，这也是模型体积被卡在 23MB 的原因（单条查询 CPU 2ms）。

降级口径与扉页分话一致：模型不在，`dim()` 返回 `None`，同步不写向量、检索返回空数组、状态出口报 `encoder_unavailable`，**关键词链路一切照常**。空结果一律带 `reason`，因为"库里没有意思相近的台词"和"这台机器没装模型"在响应体上必须长得不一样（`vectors_missing` / `dim_mismatch` 同理，前者是向量落后，后者是换了模型没重建）。

**运行时同样是可选的**：`onnxruntime` + `tokenizers`（约 70MB）不进 `backend/requirements.txt`，按 `DEPLOYMENT.md` §5.1.2 那条 `pip install` 自行加装。这两包只为"线上编码那一句问题"的 2ms 服务，不该让每台部署为一条可选能力多背体积；基础镜像因此维持原样。

已知的不完美，记下来免得被当成 bug：`paratext` 不进向量库（后记语料密度低且易把风格带歪，但表已留着，将来要扩语义风格库不必重跑 OCR）；短于 4 字的台词不建向量（`'下'`、`'对不起'` 没有语义可谈，只会把余弦分布压平）；弱项是抽象动词（「分手」「打不过敌人」在本语料里返回噪声），因为语料本身是脏 OCR 短句��不是模型不行。

**消费方本阶段只有 agent**（2026-09-23 补记）：语义出口只给 MCP 与 HTTP 调用方，书架 Web 端不设入口——抽象动词的召回仍是噪声，给人用的入口会先暴露最弱的一面。要加入口，另走 `docs/agents/ui.md` 的评审流程。
