# ADR 0028 — 台词语义召回：独立出口，不与关键词混排

> 2026-11-22 更新：OCR HTTP 同步入口已由 [ADR 0041](./0041-ocr-file-extraction-boundary.md) 撤销；现在使用本机 CLI 增量同步，本文中的原接口描述仅记录历史。

> 同日补充：向量按 64 条磁盘暂存，失败状态独立于关键词；CLI 返回实际编码失败，普通重跑补向量。
> 同步入口为 `python -m app.ocr.sync`，模型内容指纹参与完成状态；小库缓存、大库每块 1024 条精确召回。
> 以下编码失败仅记日志及全库矩阵内存描述为历史，当前资源边界见 `DEPLOYMENT.md` §5.1.3。

> **2026-11-23 修订**：存量向量缺少生成签名或同步元数据时以 `model_mismatch` 阻断语义召回，保留数据并等待本机同步补建。
> 模型会话、维度和签名整体发布，单次编码固定状态，查询与每批建库核对预期签名。关键词检索保持可用；
> 这些防护使用标准库，不改变默认镜像的推理依赖清单。

- **日期**：2026-09-23
- **状态**：Accepted

台词检索此前只有一条腿：FTS5 trigram 字面匹配（简繁归一后已做到字形无关，见 ADR 0017 修订）。字面不通的查询完全落空——搜「告白」拿不到「我喜欢你」，搜「脸红」拿不到「满脸通红」。本轮补上第二条腿：量化 `bge-small-zh-v1.5`（ONNX，23MB）把台词与问题都编成 512 维归一向量，余弦取近邻。

三条决定各自否决了什么：

**一、语义只做成独立出口（`GET /api/search/dialogue-semantic` 与 MCP `search_by_meaning`），不并进 `search_dialogues` 做混合排序。** 现有关键词出口的排序里掺了本人视角（收藏、完读率、站内热度，ADR 0017 决策 9），`rank_score` 又是"本次候选池内 min-max 归一"——换一次查询就换一把尺子。把余弦相似度塞进同一根标尺，前端与 agent 都无法区分"这句意思像"和"这本你读过"，而混合排序要重测的口径（错题本 #139 的"计数字段与身份无关"）比语义召回本身的价值大得多。因此新出口用**独立字段 `similarity`**（余弦，不做池内归一、不掺业务信号；但**只在同一次查询的结果之间比高低**——实测真命中与噪声的分数区间重叠，跨查询比较与绝对阈值都不成立，"没找到"只由 `reason` 表达）、**按页去重**返回（一页只留最相似的那个气泡，免得同一页的几个气泡挤占 top-k）、**不掺业务信号**，两个出口各自成立。要字面命中就用老出口，要换种说法也说得出就用这个。

**二、向量存在台词专库里（`comic_dialogue_vectors`），不外挂、不进识图侧。** 识图侧已是独立 Rust sidecar 自带向量索引（ADR 0026 的分域口径），文本向量与图像向量除了都叫"向量"以外没有任何共同点，混库只会让两边的重建与迁移互相牵连。同库异表可复用本机台词索引同步、删书与孤儿清理，`comic_dialogues.db` 的一致性备份也包含语义向量。

**三、语料向量由台词索引所在主机编码。** 文本编码复用本机同步流程，避免新增向量伴生格式与跨主机同步协议；画页推理仍可独立执行。向量的产出挂在 `sync_comic_dialogues` 尾部，每同步一本就补建该本向量；全量重建是显式动作（`POST /api/search/dialogue-vectors/rebuild`，仅馆长）。查询编码在服务进程内按请求执行，采用轻量模型；具体吞吐与延迟在目标环境验证。

模型或可选推理依赖不可用时，`dim()` 返回 `None`，语义召回返回 `available=false` 和 `encoder_unavailable`。
关键词索引重写时同时清除该本旧向量；关键词增量命中时保留已有向量。实际编码失败由本机 CLI 返回非零，
业务画页修改使用非严格同步，保留已提交关键词并记录向量待重试。普通同步可补建向量并清除失败状态。
其他未走检索的原因包括 `vectors_missing`、`dim_mismatch`、`model_mismatch`；问题不足两字时返回
`query_too_short`，此时 `available` 为 true。没有签名的存量向量按未核验处理，等待补建，不视为当前模型生成。

**运行时同样是可选的**：`onnxruntime` + `tokenizers` 不进 `pyproject.toml` 的默认运行时依赖，按
`DEPLOYMENT.md` §5.1.2 加装。服务端 numpy 按需导入；文件锁、签名和模型状态使用标准库。
默认 Dockerfile 以 `uv sync --locked --no-dev --inexact` 安装依赖，测试与文档不进入镜像，模型随数据卷保存。
这些改动影响后端源码层，不自动增加推理包；主动安装推理包或把模型烘焙进自定义镜像时才增加对应体积。

已知的不完美，记下来免得被当成 bug：`paratext` 不进向量库（后记语料密度低且易把风格带歪，但表已留着，将来要扩语义风格库不必重跑 OCR）；短于 4 字的台词不建向量（`'下'`、`'对不起'` 没有语义可谈，只会把余弦分布压平）；弱项是抽象动词（「分手」「打不过敌人」在本语料里返回噪声），因为语料本身是脏 OCR 短句，不是模型不行。

**消费方本阶段只有 agent**（2026-09-23 补记）：语义出口只给 MCP 与 HTTP 调用方，书架 Web 端不设入口——抽象动词的召回仍是噪声，给人用的入口会先暴露最弱的一面。要加入口，另走 `docs/agents/ui.md` 的评审流程。
