# ADR 0006 — 动态访客通行证簿与轻量级 SQLite 状态隔离架构

- **日期**：2026-08-30
- **状态**：Accepted
- **关联**：替代原 ADR 0003 中静态单一访客口令设计，承接本地优先不变量

## 背景

在最初的门禁演进中，系统曾通过单一环境变量配置访客口令。随着实际家庭与朋友分享场景的深入，静态单一访客口令暴露出显著不足：

1. **生命周期失控**：无法针对单个朋友设置有效期限，密码一旦分享便无法对单人回收，换密码会导致所有好友被踢出；
2. **缺乏个性化隔离**：红心喜欢（`favorite`）与跨端每本阅读进度（`last_page`）若混淆在一起，会导致访客的操作污染馆长的私藏和阅读进度；
3. **入馆摩擦**：朋友初次打开时若必须手动输入口令，体验不够丝滑。

同时，用户曾探讨是否需要将整体底层存储全量切换为关系数据库。经论证，纸间核心资产仍坚持**本地优先（Local-First）**与**自包含（Self-Contained）**——核心图包继续采用原子 `album.json` 扁平/多章节目录，无需数据库即可离线阅读与独立迁移。因此，需要设计一种轻量级、零负担的状态隔离方案。

## 决策

1. **存储架构分层（Dual Storage Strategy）**：
   - **静态书库元数据（原子自包含）**：继续保留 `album.json` + `pages/`，完全免维护，永不因为数据库损坏而丢书；
   - **动态状态库（轻量嵌入式）**：在 `backend/data/comic_shelf.db` 中采用 Python 原生 `sqlite3` + WAL 模式（Write-Ahead Logging），轻量管理 3 张表：
     - `guest_passes`：访客登记名册、专属 token、有效期（`expires_at`）、启停状态与印发时间；
     - `user_favorites`：基于 `(user_id, source, source_id)` 联合主键实现馆长与每位访客的独立红心标记；
     - `user_reading_progress`：基于 `(user_id, source, source_id)` 记录最新阅读进度（`last_page`），支撑跨设备多端对齐。
2. **废除单一静态访客码**：
   - 彻底废除 `COMIC_SHELF_GUEST_SECRET` 环境变量，不再支持全局写死口令；
   - 仅保留 `COMIC_SHELF_SECRET` 作为馆长最高权限管理口令。
3. **馆长控制台「访客簿」（Guest Modal）**：
   - 馆长入座后，可在顶部栏随时打开雅致的书房模态框，直观查看名册借书卡；
   - 支持印发通行证（设置 7/30/90/180天/永久有效）、就地微反馈复制（带 success 色彩渐变）、一键续期 30 天、重置密钥（旧口令即刻作废）、暂停与彻底注销；
   - 支持派发专属免密直达链接（`?token=...`），朋友初次点击即可静默鉴权入馆，且前端自动从地址栏擦除 token 参数防止二次泄漏。
4. **全局私密本子防御**：
   - 馆长标记为 `hidden_from_guest: true` 的本子，在书架列表对所有访客过滤；在详情、分章节、画页与缩略图各底层 API 均统一返回 404，访客完全无感知。

## 后果

- **安全性与可控性**：馆长可精确掌控每位朋友的访问权限与到期时间，随时换新密钥或关停，避免一人泄露全网可用；
- **体验零负担**：朋友获得免密直达链接直接看书，收藏夹与阅读进度各自独立，彻底告别数据打架；
- **零额外运维成本**：使用 Python 内置 SQLite，无需安装或运行额外的数据库服务（如 PostgreSQL/MySQL），Docker 镜像与宿主机环境无任何新增依赖。
