# ADR 0031 — 跨源作品查重、规范化标题影子索引与异源镜像关联

- **日期**：2026-09-30
- **状态**：Accepted
- **关联**：承接 ADR 0015 (万级书库分页与 SQLite 影子索引)、ADR 0030 (强制显式指定图源)；扩充 `CONTEXT.md` 跨源作品查重与异源镜像关联术语

## 背景与问题

纸间已陆续接入禁漫（`jm`）、哔咔（`picacg`）、拷贝（`copymanga`）及本地自建（`local`）等多个来源，未来还将接入更多远端图源。随着藏书向 1w ~ 5w 迈进，馆长在淘书与日常收录时面临现实挑战：

1. **同源车号遗忘**：馆长在手动收录输入车号时，无法立即感知该车号是否已在本机收录，往往在点击收录甚至发起重复网络请求后才被动感知；
2. **跨来源重复收录**：同一部漫画现实中常并存于多个图源（如禁漫车号与哔咔 ID、拷贝 pathword 互不相同），馆长极易遗忘自己已收录过该作品的其他平台版本；
3. **文本匹配失真与误报风险**：各平台作品标题附带不同格式的汉化组、展会、发售载体标签（如 `[脸肿汉化组]`、`(C101)`、`[中国翻訳]`、`[DL版]`）及繁简差异（`梓喵買醬油` vs `梓喵买酱油`）。纯字符串匹配漏报率极高，而激进的模糊相似度算法又容易把分卷作品（第 1 卷 vs 第 2 卷）误判为重复；
4. **性能疑虑**：在 1w ~ 5w 藏书体量下，若查重方案设计不当（如全表正则扫描或高复杂度文本比对），可能产生显著 I/O 阻塞。

## 方案论证与权衡（Grilling Analysis）

围绕算法边界、数据结构与交互体验，经过三轮严格的方案审问与决策收敛：

### 1. 性能基石与量级测算（1w ~ 5w）

- **技术事实**：纸间已在 `comic_shelf.db` 中建立 `comics_index` 影子索引表。SQLite B-Tree 索引对 5 万行数据单次查询树深度仅为 3 层，耗时 **< 0.1ms**；在 Python 内存中 5 万个字符串哈希表占用仅 **4 ~ 6 MB**，单次哈希比对耗时 **~50ns**。
- **决策**：在 `comics_index` 表中增加 `normalized_title` 字段并建立 B-Tree 索引（`idx_comics_index_norm_title`）。跨源查重执行极轻量的单条索引点查，**耗时微秒级，性能零瓶颈**。

### 2. 规范化标题提取规则（Normalization Boundary）

- **清洗范围**：
  1. 剥离所有成对标签：`[...]`、`(...)`、`【...】`、`（...）`、`{...}` 内容（汉化组、社团、展会、发售载体）；
  2. 繁简归一化：通过内置 `to_simplified()` 统一转为简体中文；
  3. 符号与空白清洗：折叠连续全半角空格与特殊分隔标点；
  4. 严格保留卷册标识：主干中的卷号、册号、分部（如 `01`、`Vol.2`、`前篇`、`下`）作为核心标题保留，确保分卷作品误报率为 0；
  5. 纯标签兜底保护：若剥离后主体文字为空（如 `[C100][DL版]`），自动回退使用原始标题（仅做繁简与空白折叠），杜绝空值碰撞。

### 3. 数据关系架构：动态计算 vs 持久化关系表

- **路线 A（独立实体关系表 `comic_mirrors`）**：
  - _否决理由_：多维护一张关系表，产生级联删除、双向同步开销，容易遗留孤儿数据，违反极简主义约束。
- **路线 B（基于影子索引动态查询，Accepted）**：
  - _实现原理_：各版本作为物理独立的 `(source, source_id)` 实体共存，保留各自的画质、章节与 `remote.json` 摄取血缘；
  - 在接口响应期动态通过 `WHERE normalized_title = :norm AND (source != :src OR source_id != :id)` 组装镜像关联列表。天然具备零存储冗余与修改/删除零成本自愈特性。

### 4. 全链路交互协同时机（演进至方案 3：提交时弱拦截）

经原型对比与实际体验评估，最终否决了“输入即时检测（方案 1）”的高频打扰设计，确立**方案 3：提交时弱拦截与智能导流**，契合纸间克制沉稳的阅览室直觉：

1. **收录面板（平时静默，提交时弱拦截与智能导流）**：
   - 输入框保持纯净安静，输入车号时不发起任何后台网络探测，不展示突兀的动态卡片；
   - 点击【收录到纸间】按钮时：
     - 若命中本地缓存（`from_cache=True`）：原地弱拦截，弹出温和水墨 Toast 提示「该作品已在馆内，正在为您前往《...》」，并直接平滑路由直达 `/comic/${source}/${source_id}` 详情页；
     - 若为全新收录但命中异源（`cross_matches` 存在）：正常入库并弹出琥珀色提示「收录成功，检测到馆内已存在异源同名作品：【...】《...》」，新漫画详情页顶部同样展示异源同名作品直达卡片；
   - 彻底移除了无意义的独立探测端点与冗余轮询，实现零网络开销与零界面视觉噪音。
2. **漫画详情页（异源镜像直达胶囊）**：
   - 单本详情（`GET /api/library/{source}/{source_id}`）响应携带 `mirrors`；
   - 标题下方展示古雅水墨胶囊条「馆内亦藏有：【图源】《书名》」，点击无缝跨源切换，支持多版本自主比对。
3. **发现榜单导流（Discovery Feed）**：
   - 榜单卡片在拉取时同步比对书库，对跨源已收录作品右上角盖上赭黄色「异源同本印章（馆内已有 · 来源）」，并提供一键看馆内版本动作。
4. **批量收录执行策略（Batch Import）**：
   - `shelf_batch_import_comics` 遇到异源重复作品不中断，继续收录并在结果与诊断日志中记录警告，确保调用方知情且数据完整。

## 架构契约与极简主义

### 1. 数据库影子索引表（`comics_index`）变更

```sql
ALTER TABLE comics_index ADD COLUMN normalized_title TEXT NOT NULL DEFAULT '';
CREATE INDEX IF NOT EXISTS idx_comics_index_norm_title ON comics_index(normalized_title);
```

系统启动与数据落盘（`upsert_comic_index`）时自动计算并自愈回填，`upsert_comic_index` 确保在任何元数据写入时自动调用 `normalize_title` 同步维护该字段。

### 2. 接口契约极简复用

遵从“不为单一功能引入多余抽象”原则，**不新增独立的查重端点**，完全复用现有业务链路：

1. **收录端点增强（`POST /api/library/import`）**：
   响应模型 `ImportResult` 增补 `cross_matches: list[DuplicateCheckMatch] = []`。
   - 若本地已收录，返回 `from_cache: true` 及 `cross_matches`；
   - 若初次入库，返回 `from_cache: false` 及可能存在的 `cross_matches`。
2. **单本详情端点扩展（`GET /api/library/{source}/{source_id}`）**：
   响应模型 `ComicDetail` 增补 `mirrors: list[DuplicateCheckMatch] = []`，供详情页标题下方呈现水墨导流卡片。
   - **隐私隔离不变式**：查询函数 `find_comic_mirrors(..., is_curator=...)` 严格区分访客权限，非馆长时强制注入 `AND hidden_from_guest = 0`，绝对阻断访客通过异源作品刺探隐藏藏书。
3. **发现榜单端点扩展（`GET /api/discovery/ranking`）**：
   响应模型 `DiscoveryItem` 增补 `mirror_source: str | None` 与 `mirror_source_id: str | None`。

## 收益

1. **彻底消除遗忘重复收录**：同源输入即时感知、跨源入库与榜单全链路透传，避免无谓的重复抓取与磁盘浪费；
2. **微秒级性能，零并发负担**：得益于预计算 B-Tree 索引，即使 5 万本藏书规模，查重计算亦在 0.1ms 内完成；
3. **多版本自主权归于馆长**：既不粗暴硬性阻断，也不破坏各自的数据血缘，保持各图源版本独立共存与自由比对。
