# ADR 0033 — 浏览器扩展一键收录与跨源右键入库架构

- **日期**：2026-10-07
- **状态**：Accepted

## 背景与问题

纸间作为本地优先的单体漫画收藏馆，核心价值在于让馆长能够将散落在各大图源（禁漫天堂、哔咔漫画、拷贝漫画等）的优质本子系统化纳进私人书库。此前，馆长在第三方站点浏览淘书时，收录流程通常为：

1. 复制网页链接或寻找车号；
2. 切换回纸间标签页，点击「收录漫画」按钮并粘贴；
3. 繁琐的手动交互严重阻断淘书流，且在海量翻阅与检索列表中开销巨大。

为了将收录动作压缩至极致的 1 步，需要设计专属的 Chrome 浏览器扩展。然而，在扩展与纸间服务端的协同架构上，存在以下核心权衡：

1. **多仓割裂 vs 单仓同构维护**：单独建立扩展仓库易发生 API 契约与领域模型漂移；
2. **重型框架 vs 原生轻量**：现代扩展常引入 Vue/React/WXT 等框架打包，但对于收录扩展而言极易造成过度工程化与冷启动延迟；
3. **DOM Content Script 侵入 vs Service Worker 宿主隔离**：在目标站点注入 UI 弹窗容易遭遇目标站 CSP、反爬防护与样式污染；
4. **频繁换域与图源判定**：尤其禁漫（18comic）镜像与分流域名繁多，必须保证提取车号与图源时的鲁棒性与确定性（严守 [ADR 0030](./0030-explicit-provider-source-for-comic-import.md)「全链路显式指定 source」）。

## 核心决策

### 一、单仓同构与极致精简交付

1. **源码内聚在 `extension/` 目录**：
   - 随主工程同步演进，依托现有 Node 工具链，在 `package.json` 提供 `pnpm build:ext` 脚本；
   - 产出解压即用的 `dist/extension/` 与 GitHub Release 附件 `dist/paper-room-extension.zip`（体积 < 50KB）。
2. **纯原生 Web 标准 (Vanilla MV3)**：
   - 采用标准 Manifest V3，仅由 `service-worker.js` 与原生精简 `options.html` 组成；
   - 坚决杜绝重型 UI 框架与历史记录面板，贯彻「无感即最佳」理念。

### 二、双模右键菜单与零 DOM 侵入反馈

1. **双模智能提取**：
   - **超链接右键**（`contexts: ["link"]`）：在漫画目录/列表/搜索页直接右键本子卡片链接触发收录，淘书时无需逐个新开标签页；
   - **页面空白处右键**（`contexts: ["page"]`）：在已打开的漫画详情页或阅读器内空白处右键触发收录。
2. **确定性图源解析引擎**：
   - 禁漫天堂（`jm`）：严格限定相册车号 `album_id` 匹配 `/album/(\d+)`，支持官方主站及所有已知内地/东南亚分流镜像；若用户在单话阅读页（`/photo/`）空白处右键，借助 `activeTab` 瞬时权限遍历 DOM 链接或内嵌 `<script>` 标签提取所属相册车号并自愈重定向；若未能提取则显式拦截，绝不允许单话分卷 ID（`photo_id`）穿透至服务端；
   - 哔咔漫画（`picacg`）：匹配 `/(?:comic|comics)/([0-9a-fA-F]{24})`；
   - 拷贝漫画（`copymanga`）：匹配 `/comic/([a-zA-Z0-9_\-\.]+)`。
   - 严格向纸间 API `POST /api/library/import` 显式提交 `{ id, source }`，符合 ADR 0030。
3. **原生通知与直达链路**：
   - 彻底摒弃注入页面常驻 Content Script 的做法，免疫任何第三方站点的 CSP 安全策略阻断；
   - 使用系统原生通知（`chrome.notifications`）与图标 Badge 反馈收录结果，色彩严格遵循 `src/styles/tokens.css` 设计令牌（成功墨绿 `#3f6d4e`、在库琥珀 `#d97706`、报错朱红 `#e5484d`）；
   - 通过 `chrome.storage.local` 持久化通知链接，彻底规避 Manifest V3 Service Worker 闲置休眠导致内存映射丢失的问题；点击通知卡片随时直达纸间阅览室详情页（`{serverUrl}/comic/{source}/{source_id}`）；浏览器启动时自动清理陈旧通知 Key；
   - `buildUrlPatterns` 严格过滤前导通配符并区分 IPv4 地址，在 `chrome.contextMenus.create` 设置异常捕获并平滑降级至内置默认规则，杜绝菜单因规则非法而静默崩溃。
   - **通知推送可控与静默模式**：选项页提供即时保存的「接收系统通知推送」开关；关闭时彻底阻断系统弹窗气泡，仅通过工具栏图标彩色短角标反馈状态，彻底规避操作系统专注助手/通知中心对声音和横幅的静默拦截。

### 三、智能上下文直达与极简配置

1. **工具栏图标上下文智能直达**：
   - **在漫画页面点击**：自动识别图源与车号，直接在新标签页打开纸间该本子详情页（`${serverUrl}/comic/{source}/{id}`），后台静默预热确保入库；纯跳转上下文保持静默，严禁在图标闪烁「已在」或「✓」角标与通知，避免用户对「是否误触发添加」产生认知混淆；
   - **在常规网页点击**：直达纸间书架主站。遵循单一职责原则，不引入从纸间向外逆向跳出的冗余抽象。
2. **Chrome 原生选项页 (`options_ui`) 与图源分流管理**：
   - 贯彻纸间设计系统（`tokens.css`）与案头卡片目录隐喻，支持亮暗双模与 WCAG AA 高保真对比度；
   - 提供「纸间服务地址」与「馆长访问口令」配置，支持一键「测试连接」验证权限与异步加载防抖；
   - 提供即时自动落盘的「接收系统通知推送」独立开关；
   - 设立「图源分流域名」管理体系：通过现代 CSS `::details-content` 原生动画收纳三大图源 20 个内置官方与镜像域名（只读）；支持馆长等宽胶囊芯片群（Tag Chips）自由追加与移除自定义分流镜像，具备单提交语义、草稿脏状态逃生与焦点回退保障。

## 效果与收益

1. **收录体验跃升**：淘书时鼠标右键「一键收录」，秒级响应，彻底消除繁琐复制切换；
2. **高抗逆力与稳定性**：纯 Service Worker 架构不依赖第三方网页 DOM 与生命周期，对各种反爬、CSP 策略与换域具备极强免疫力；
3. **交付极其轻量**：整包体积仅 46KB，零复杂依赖，加载速度 0ms，开箱即用。
