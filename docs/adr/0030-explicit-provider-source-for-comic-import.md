# ADR 0030 — 漫画收录强制显式指定图源与批量收录同构化

- **日期**：2026-09-26
- **状态**：Accepted

## 背景与问题

纸间此前在前端 WebMCP 层的单本收录（`shelf_import_comic`）与批量收录（`shelf_batch_import_comics`）中，为了调用便捷提供了基于正则和字符串特征的图源“智能推断”逻辑：

- 以 `/`、`./`、`public/` 开头识别为 `local` 本地图集；
- 包含 `picacomic`、`picawang` 或为 24 位十六进制识别为 `picacg` 哔咔画卷；
- 其余情况均默认静默回退至 `jm` 禁漫。

同时，后端 FastAPI 的 `ImportRequest` 数据模型中亦残留历史默认值 `source: str = "jm"`。

随着纸间多图源架构的持续扩展（后续接入 nhentai、hitomi 等更多远端图源以及本地多样化目录）：

1. **车号命名空间严重冲突**：多个平台的车号均呈现 5~7 位纯数字特征（如禁漫与 nhentai 车号长度完全重合），低层启发式规则根本无法分辨其所属平台；
2. **静默回退带来脏数据与混淆**：当用户或智能体输入拼写错误或新平台标识符时，底层静默兜底为 `jm` 会向禁漫错误发起请求，导致莫名 404 或误收录完全无关的禁漫漫画；
3. **职责越界**：语义理解与平台判定应是调用层（用户交互与 Agent 决策中枢）的职责，底层基础设施与执行工具必须保证百分之百的确定性与幂等性。

## 核心决策

### 一、全链路收紧收录契约：`source` 作为一等必填真理参数

1. **废除启发式嗅探与默认回退**：
   - 彻底移除 `importOneComic` 中的 URL 关键词嗅探、正则匹配以及静默 fallback 到 `jm` 的所有代码分支；
   - 任何层级的收录操作必须显式传入 `source`（枚举 `['jm', 'picacg', 'local']`）。
2. **后端 API 与前端类型定义严格同步**：
   - 服务端 `backend/app/models.py` 中 `ImportRequest.source` 移除 `= "jm"` 默认值，改为严格必填字段 `source: str`，杜绝任何历史偏袒；
   - 前端 `src/types/index.ts` 中 `ImportRequest.source?: string` 收敛为 `source: string`。
3. **本地自建图集规范化**：
   - 本地图集收录一律声明 `source: 'local'`，路径通过 `id` 传入（保留 `local_path` 兼容同义别名）。
4. **职责归位与冗余代码剥离**：
   - 前端彻底移除对特定图源标识符的局部正则嗅探（如原先冗余的哔咔 24 位 Hex 提取）及中间转接变量，输入透传至后端，统一由对应 Provider 的 `normalize_id` 担当规范化唯一真理源。

### 二、WebMCP 工具双重门禁与友好报错

1. **Schema 结构化约束**：
   - `shelf_import_comic` 的 `inputSchema.required` 显式声明 `['source']`；
   - `shelf_batch_import_comics` 的 `inputSchema.required` 显式声明 `['items', 'source']`。
2. **运行时防御性阻断**：
   - 若调用方因上下文脱节或旧脚本遗漏 `source`，运行时在最前端立即抛出具象中文异常：
     `"收录漫画必须显式指定来源 Provider (source: "jm" | "picacg" | "local")，为杜绝多平台车号冲突，系统已不再提供隐式猜测。"`；
   - 错误通过 Model Context Protocol 规范包装为 `{ content: [...], isError: true }`，使智能体能够精准自我纠错并带上正确图源重试。

### 三、批量收录单批次同构化与单项错误隔离

1. **单批次严格同源（Homogeneous Batch）**：
   - 一次 `shelf_batch_import_comics` 任务严格锁定单一 `source`，批次内部 5 秒防风控节流与状态统计在同源上下文中有序推进；
   - 若调用者持有混合来源清单，必须由上层智能体负责按图源分组，拆分为多次同源批量任务发起。
2. **格式校验与单项错误隔离**：
   - 批次执行过程中，由具体 Provider 的 `normalize_id` 执行单项车号规整与校验；
   - 若某单项车号不符合当前声明的 `source` 规范，该项标记为 `status: 'failed'` 并记录原因，批次内其余合法车号继续执行，绝不因单条手误导致整批 50 本任务中断。

## 效果与收益

1. **消除图源碰撞隐患**：彻底杜绝多平台间纯数字或哈希车号的交叉误判，保障本地典藏书库的数据血缘纯洁；
2. **架构确定性提升**：工具层契约纯粹无黑盒，各端点语义对齐，符合本地优先与领域驱动设计的不变量；
3. **Agent 自愈韧性增强**：明确的 Schema 描述与精准的拦截错误信息引导模型上下文在工具调度时主动指定图源或反问确认。
