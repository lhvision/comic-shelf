# ADR 0040 — 浏览器扩展分流域名强绑定图源与全局唯一互斥架构

- **日期**：2026-11-12
- **状态**：Accepted

## 背景与问题

纸间在 [ADR 0033](./0033-browser-extension-ingest-and-cross-site-right-click.md) 中设立了浏览器扩展一键收录与分流域名管理机制。然而，在最初的实现中存在两个关键的领域模型与架构缺陷：

1. **自定义域名与图源脱节**：
   - 选项页将用户添加的自定义分流域名存储为扁平一维数组（`customDomains: string[]`），界面上孤立为一个全局胶囊列表；
   - 用户无法得知新添加的域名具体归属于哪一个图源（禁漫天堂、哔咔漫画还是拷贝漫画），视觉认知断层且容易导致配置错乱；
2. **违背图源显式确定性不变量**：
   - [ADR 0030](./0030-explicit-provider-source-for-comic-import.md) 确立了「全站收录操作必须由调用方显式指定来源，禁止跨来源模糊推断」的核心不变量；
   - 但此前 Service Worker 仅将域名作为粗筛白名单，在 `resolveComicInfo` 中仍采用硬编码阶梯正则盲猜图源（如 `/album/` 算禁漫、24 位十六进制算哔咔、其余 `/comic/` 算拷贝）。这导致若拷贝漫画作品的车号 slug 碰巧是 24 位十六进制，会被误判为哔咔并向错误图源发起收录；
3. **缺乏全局域名排重门禁**：
   - 扁平数组未在图源间设立互斥约束，用户可能将同一域名重复添加至不同图源，或重复添加已有内置分流。

## 核心决策

### 一、领域实体与存储结构升级

1. **图源分流字典化（CustomDomainsMap）**：
   - `chrome.storage.local` 中的 `customDomains` 从 `string[]` 升级为按图源键名绑定的对象字典：
     ```ts
     interface CustomDomainsMap {
       jm: string[]
       picacg: string[]
       copymanga: string[]
     }
     ```
   - 每一个分流域名在领域中必须且只能归属于唯一的远端图源（`source`），禁止无归属的游离域名。
2. **存量历史配置平滑自愈迁移**：
   - 扩展加载（`onInstalled`、`onStartup` 及选项页初始化）时，若检测到存量配置为一维数组，通过 `migrateCustomDomains()` 自动执行启发式分类：
     - 包含 `18comic` 或 `jm` 归入 `jm`；包含 `pica` 归入 `picacg`；包含 `copy` 或 `manga` 归入 `copymanga`；其余保守归入 `jm`；
     - 自动剔除系统内置域名及已迁移重复项，单向写回存储完成升级，老用户配置零丢失。

### 二、严格的全局域名唯一性约束（Global Domain Uniqueness）

1. **全系统单一真理源排重**：
   - 任何域名在全系统（3 大图源的 11 个内置分流 + 所有图源的自定义分流）中**只能出现一次**；
   - 录入时通过 `findDomainOwner(domain, customMap)` 进行全局扫描：
     - 若命中内置分流：拦截并提示 `已在【{图源名}】官方内置中`；
     - 若命中当前图源自定义：拦截并提示 `已在【{图源名}】自定义分流中`；
     - 若被其他图源占用：拦截并明确提示 `已属于【{冲突图源名}】自定义分流，不可跨图源重复配置`。

### 三、选项页视觉整合与智能交互

1. **输入栏图源选择与智能预判**：
   - 在域名输入框前置图源选择下拉框（禁漫天堂 / 哔咔漫画 / 拷贝漫画）；
   - 用户输入或粘贴时实时触发 `guessProviderFromDomain()`，匹配到明显特征（如 `comic18`、`manhuapica`、`mangacopy`）时自动为用户切换目标图源，并给出友好内联提示，兼顾批量录入效率与防错。
2. **三大图源统一专属面板**：
   - 彻底废除孤立的自定义 Chips 区域与底部的折叠抽屉；
   - 界面按三大图源卡片（禁漫、哔咔、拷贝）就地划分，每个卡片内部清晰展示：
     - 该图源总分流统计（自定义数 + 内置数）；
     - 该图源专属的自定义分流胶囊（支持无障碍键盘焦点回溯删除）；
     - 该图源专属的官方内置分流折叠抽屉（只读）。

### 四、后台流水线：域名反查图源锁定专用提取器

1. **域名反查图源锁定（Domain-Driven Source Resolution）**：
   - 捕获目标 URL 后，首先通过 `matchDomainToProvider(hostname, customMap)` 精确反查出当前域名所属的 `source`；
   - 仅将解析请求路由至该 `source` 专有的提取逻辑，杜绝跨图源正则盲猜：
     - 若命中 `copymanga` 分流，即使 slug 为 24 位十六进制，也严格按照拷贝漫画规则提取，绝不穿透至哔咔；
     - 若 URL 路径不匹配该图源的合法规则，提示 `目标链接未能识别为有效的【{图源名}】漫画页面`，杜绝误收录与静默脏数据。

## 效果与收益

1. **彻底消除认知错乱**：自定义域名与内置域名在视觉和逻辑上统一归属于三大图源，用户对分流资产一目了然；
2. **坚守显式指定来源不变量**：收录上下文在域名匹配阶段即锁定图源，从源头根治多平台车号与路径格式碰撞；
3. **老用户零感知自愈**：平滑升级迁移算法确保历史自定义域名自动归类、自动去重并升级至全新存储模型。
